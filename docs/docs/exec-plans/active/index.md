## A-001 商品管理接入「可售」筛选与标签

- **背景**：后端已支持 `GET /api/products?sellState=sellable|unsellable|unknown` 与 `?sellableSite=de,uk`，界面还没暴露；用户只能靠卡片上的「可售站点」标签肉眼筛。
- **目标**：筛选面板加「可售状态」「可售站点」两项；卡片 BG 徽标旁显示 `sellState` 摘要。
- **验收**：选「可售 + UK」后列表条数与接口返回一致；清空筛选恢复。
- **影响面**：`lib/client.js`（筛选面板 + ProductPage state）、`erp/server.js`（无需改，参数已支持）。
- **状态**：待开始（P0）

## A-002 站点数据「没有」与「没采到」的区分

- **背景**：非商品所在站点经常没有排名，卡片显示 `未上榜`；用户会误以为漏采。
- **目标**：卡片/详情把 `siteStats[站点]` 分成三态：有值 / 数据源无该站记录 / 未请求过该站。
- **验收**：未请求过的站点显示 `—` 且有 tooltip 说明；数据源无记录显示 `未上榜`。
- **影响面**：`erp/server.js`（站点数据写入时打标记）、`lib/client.js`（渲染）。
- **状态**：待开始（P0）

## A-003 货币选择落到入库口径

- **背景**：多链接采集表单已能选货币，但只切采集浏览器币种；入库价格仍以智赢按站点返回为准。
- **目标**：若用户选了「统一币种」，入库时按 `rates.json` 换算并打 `currencySrc='converted'` 标记（保留原币值）。
- **验收**：同一商品在两站点采集后 `price` 币种一致且 `origCurrency/origPrice` 可追溯。
- **影响面**：`erp/server.js`（merge/入库）、`rates.json`、导出列。
- **状态**：设计待确认（P1）

## A-004 采集任务可视化（多任务队列）

- **背景**：`collectProgress` 是单份状态，连续触发采集时用户只能看到最后一个。
- **目标**：`/api/collect/jobs` 返回任务列表（运行/排队/完成），界面显示队列。
- **验收**：连续点击 3 种采集，界面能看到 3 条任务及各自状态。
- **影响面**：`erp/server.js`（任务注册表）、`lib/client.js`。
- **状态**：待开始（P1）
