# PRODUCT_SENSE.md — 产品定位与判断标准

> 写代码时的「为什么」：这个产品给谁用、解决什么、什么算做对了。

---

## 1. 一句话定位

**给亚马逊跟卖/铺货卖家的选品与上架工作台**：从一个 Amazon 列表页出发，批量拿到商品的品牌、排名、配送方式、跟卖情况、能否在你已授权的店铺里销售（BG），算出可承受的售价，然后一键推到 ifast 上架。

---

## 2. 用户与场景

| 角色 | 典型动作 | 关键诉求 |
|---|---|---|
| 跟卖卖家（主用户） | 找能跟的品 → 看 BG 能不能卖 → 算承受价 → 上架 | **快**、**别上不能卖的品**、**价格不亏** |
| 铺货/精品选品 | 类目/关键词批量采集 → 按需求强度、跟卖数、价格带筛 | 数据全、可导出、可复盘 |
| 运营/助手 | 每天跑固定链接、补采、看采集记录 | 可自动化（Agent 工具 + API） |

---

## 3. 核心闭环

```
① 采集（列表页/类目/店铺/多链接/跟卖卖家）
      ↓  自动
② BG 检测（用你已授权的 5 个店铺账号，逐店问"这个 ASIN 我能不能卖"）
      ↓  自动
③ 按店铺分类可售（sellableSites / sellState）→ 只对可售站点补排名/配送/价格
      ↓  人看
④ 商品管理筛选（可售 + 排名 + 跟卖数 + 价格带 + 品牌风险）
      ↓  人看
⑤ 算价（采购 + 运费 → 利润率 → 承受价；面板里还能微调 ±）
      ↓  人点
⑥ 上架 ifast（多店铺、多变体，可选提交亚马逊）+ 本地台账防重复
      ↓
⑦ 复盘（采集记录、上架记录、归档）
```

**这条链上任何一步"数据是假的"，后面全错** —— 所以产品第一价值观是数据真实性（见 DESIGN.md §1）。

---

## 4. 功能地图与验收点

| # | 功能 | 用户看什么 | 验收标准 |
|---|---|---|---|
| 1 | 列表页采集 | 采集面板进度、采集记录 | 抓到的条数 = 入库条数（去重后）；失败有原因 |
| 2 | BG 检测 | 卡片/面板上的店铺徽标 | 5 个店铺各自状态；`ERROR` 会重试；24h 内不重复打接口 |
| 3 | 可售分类 | `可售站点 DE/ES/FR/IT/UK` | 没测过 = `unknown`；测过全不可售 = `unsellable`；两个站点可售就两个 |
| 4 | 多站点数据 | 卡片 6 行表格 | 每站 排名/配送/价格/上架 都在；没数据显 `—` 不显 0 |
| 5 | 商品管理筛选 | 数量变化 | 可售状态/站点/排名/跟卖/价格/品牌 筛选与卡片一致 |
| 6 | 算价 | 承受价、净利 | 与定价表口径一致（K=0.68/0.85、德国 −3） |
| 7 | 上架 | ifast 记录、台账 | 同 ASIN 同站点不重复；`siteId` 按账号实时取 |
| 8 | 浏览器面板 | Amazon 页右侧 🍟 | 字段与库一致；改过的初始价切页不丢；当前变体 ASIN 蓝色 |
| 9 | 知产查重 | 风险等级 | 按目标站点查，给出可执行结论（能/不能上） |
| 10 | 导出 | xlsx/csv | 列与界面口径一致（尤其"大排名"） |

## 5. 判断"做对了"的标准

1. **能卖的先看到**：用户打开商品管理，第一眼应该能筛出"可售且有排名"的品。
2. **不能卖的别浪费额度**：不可售站点不应该再去拉站点数据。
3. **数字对得上**：卡片显示的价格 = 上架时提交的价格 = 导出里的价格（同一口径）。
4. **失败能说清楚**：抓 0 条时，用户/Agent 能一眼知道是 cookie、风控、链接类型还是站点不匹配。
5. **不骗人**：`null` 就是没采到，不拿 0 或猜的值糊弄。

---

## 6. 不做什么（范围边界）

- 不做亚马逊账号注册/养号/风控对抗（只读页面 + 已授权店铺接口）。
- 不做自动改价/自动跟价（有 `reprice` 接口，但不是核心闭环）。
- 不做脱离本地环境的云端服务（全部本地 3088 + 本地数据文件）。
- 不替用户判断"能不能卖"之外的合规问题（知产风险只给参考等级）。

---

## 7. 关键口径（产品必须一致）

| 口径 | 定义 | 备注 |
|---|---|---|
| 大排名 / 父类排名 | `rankParent`（宽类目） | 缺失 = `null`，绝不拿子类顶 |
| 子类排名 | `rankChild`（细类目） | — |
| 跟卖数 | `followCount` / `sellerCount` | 来自 offers 数量 |
| 中国卖家 | `chinaSeller` | SellerCountry 为 CN/HK/TW/MO 或 ShipsFrom 推断 |
| 配送 | `fulfill` = AMZ / FBA / FBM | `amazonSell=true` 优先显示 AMZ |
| 承受价 | `(采购+运费)×(1+利润率)÷K÷汇率 + ±` | K：UK/DE 0.68、AU 0.85；德国默认 ± −3 |
| 可售 | BG 状态 `OK` | 按店铺分别判定，见 `bgByAccount` |

---

## 8. 用户最常抱怨的三件事（产品要盯）

1. **"抓不到"** → 采集抓 0 条（cookie/风控/链接类型/站点不匹配）→ 已有 `hc-probe` 与报错现场。
2. **"数据不全"** → 卡片缺字段/口径不一致 → 卡片表格 + `null` 语义。
3. **"改了又变回去"** → 面板输入被重算覆盖 → 初始价按 ASIN 锁定（2026-11-22）。
